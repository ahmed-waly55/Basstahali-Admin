# ربط عمليات أدمن بسطهالي

التنفيذ يحافظ على Angular 21 وAngular Material وTailwind. استجابة لطلب إصلاح `npm audit` حُدّثت تصحيحات Angular الأمنية داخل الإصدار 21، واستُبدلت مكتبة `xlsx` القديمة بمكتبة `write-excel-file` مع الحفاظ على التقرير العربي. راجع `security-audit.md`. العقود مبنية على نصي Swagger اللذين أرسلهما المستخدم؛ الاختبارات تستخدم HTTP محاكى، ولا تثبت صلاحيات حساب حقيقي أو سلوك الباك إند الفعلي.

| الشاشة | العمليات التي أضيفت أو اكتمل ربطها |
| --- | --- |
| الطلاب `/users/students` | POST إنشاء، GET تفاصيل، PUT تعديل، DELETE أرشفة، GET الأرشيف، POST استعادة وحصص تعويضية، PATCH نظام الحصص |
| المشرفون `/users/admins` | PUT التعديل الصحيح مع الحالة والراتب والعملة، واستكمال حقول POST؛ إزالة البيانات الوهمية والنجاح الوهمي عند الفشل |

## حماية البيانات وإعادة المحاولة

- لا تتغير القوائم على أساس نجاح محلي بعد فشل الطلب أو `success: false`.
- مفاتيح الدفع والحضور والحصص التعويضية ترتبط بمحتوى العملية وتبقى ثابتة لإعادة المحاولة. إغلاق الفترة يستخدم `Idempotency-Key` في الهيدر ويحفظه خلال الجلسة.
- إضافة دفعة رصيد الحصص لا توثق مفتاحًا لمنع التكرار؛ عند نتيجة شبكة غير مؤكدة تُحدّث القائمة وتطلب الواجهة مراجعتها قبل إعادة المحاولة الصريحة.
- إذا لم يرجع الخادم قائمة مواد الطالب كاملة، يتطلب التعديل مراجعتها صراحة قبل الحفظ. إسنادات المعلمين والطابع الزمني الأصلي لانتهاء الاشتراك محفوظة.
- أوقات نماذج المدفوعات المحلية تُحوّل إلى ISO UTC؛ التواريخ دون وقت تُرسل دون تحويل منطقة زمنية.
- تعديل الطالب يحافظ على `expirationDate: null` و`educationStageId: null` عند ورودهما من الخادم، دون فرض تاريخ اشتراك أو مرحلة غير موجودة. متطلبات إنشاء طالب جديد تبقى كما هي.

## صفحات القوائم

- أُزيلت جميع صفحات الجدولة، وروابطها من القائمة والبحث والمهام اليومية، وملخصها من الرئيسية. الروابط القديمة `/schedule` و`/student-schedules` تعيد المستخدم إلى الرئيسية؛ لا تُرسل الواجهة طلبات إدارة الجداول.
- قوائم الطلاب والمعلمين والمشرفين ترسل `PageNumber` و`PageSize` و`Search` بأسمائها الموثقة في المستودع المرجعي. الصفحة الأولى افتراضيًا 20 سجلًا؛ البحث أو تغيير الحجم يعيد للصفحة الأولى.
- `data.items` تُعرض كصفحة خادم كاملة دون تقسيمها محليًا مرة ثانية. العدد والصفحات وأزرار التالي والسابق تعتمد على `totalCount` و`totalPages` و`hasPreviousPage` و`hasNextPage`؛ العدد المفقود يظهر كغير متاح ولا يُستنتج من حجم الصفحة.
- الاستجابة القديمة على هيئة array تدعم تقسيمًا محليًا معلنًا في الواجهة. تصفية حالة الطالب وترتيبه وتصدير CSV تخص السجلات المعروضة في الصفحة الحالية؛ البحث النصي يُرسل للخادم.
- الطلبات القديمة لا تستبدل نتائج بحث أحدث، وفشل الطلب لا يعرض إجماليات تخص بحثًا سابقًا. إعادة المحاولة تحتفظ بالصفحة والبحث المطلوبين، وحذف آخر سجل في صفحة يعيد إلى صفحة صالحة.
- خيارات المعلمين في تعديل الطالب تتابع الصفحات التي يعلن عنها الخادم حتى تتاح سجلات ما بعد الصفحة الأولى.

هذه العقود مبنية على استجابات المستخدم وعلى [Basstahali-Dashboard](https://github.com/ahmed-waly55/Basstahali-Dashboard/tree/40b8b47). تحديثات التبعيات الأمنية موثقة في `security-audit.md`.

## حدود التوثيق

- لم يرد GET للمراحل التعليمية، ولا جسم PUT `/education-stages/{id}`؛ لم تُخمن هذه العقود. إنشاء المرحلة يعرض المعرّف عند وروده من الخادم، ويمكن استخدام معرف مرحلة معروف.
- قيم الدور الوظيفي، حالات قرارات تعديلات المستحقات، و`payroll.targetType` ليست مفصلة. تُستخدم المدخلات النصية أو القيمة الواردة من الخادم، دون قائمة قيم مخترعة.
- القوائم غير المذكورة أعلاه تحتفظ بعقودها الحالية؛ الصيغ غير المعروفة تُظهر خطأ، ولا تُعامل الصفحة الأولى باعتبارها جميع سجلات الخادم.
- لم تُضف endpoints خاصة بالطالب `/me` أو webhooks الدفع إلى لوحة الأدمن. مسارات الكتابة التي لم يرفق لها جسم الطلب، مثل بعض عمليات الأسئلة والمواد والمحادثات، تحتاج توثيقًا كاملًا قبل ربطها. PATCH الملف الأكاديمي للمعلم يكرر قدرة PUT الموجودة، فاحتفظنا بالتعديل الحالي.
- نطاق `api.basstahali.com` محفوظ ضمن مسودة إعدادات البيئة، لكن الوصول الفعلي كان محظورًا. يلزم تفعيل الإعدادات وحساب اختبار لإجراء تحقق فعلي من الصلاحيات والبيانات.

## التحقق

```bash
npm ci
npm run build
bash scripts/test-admin.sh
npm start -- --host 0.0.0.0 --port 4200
```

`test-admin.sh` يشغّل الاختبارات المركزة للعمليات المعدّلة مع ملف إعداد TypeScript مستقل. الجناح الافتراضي القديم يحتوي على اختبارات غير محدثة، منها توقع عنوان `Hello, admin` القديم واختبارات مولّدة دون مزودي الخدمات؛ لم نخف هذه الاختبارات أو نعدّل التطبيق لإرضائها.

فحص المتصفح المحلي في `/workspace/setup/browser/admin-flows.cjs` يتحقق من حمولة POST/PUT للطلاب، تعديل المصروف، تحميل صفحات الإدارة الأربع الجديدة، وعرض الديسكتوب والموبايل باستخدام استجابات محاكاة فقط. الصور في `/workspace/setup/` تعرض بيانات اختبار.

اختبارات القوائم تتحقق من الوصول للسجل 21 عبر صفحات الطلاب والمعلمين والمشرفين، البحث وتغيير حجم الصفحة، والحفاظ على حقول الطالب الفارغة عند التعديل، باستخدام HTTP محاكى.

## تجربة الإدارة والمظهر

- التنقل موزّع إلى نظرة عامة، التعليم والطلاب، المالية، وإدارة النظام.
- الشريط العلوي يعرض موقع الصفحة، ويتيح الانتقال السريع بين الصفحات بـ `Ctrl+K` أو `Cmd+K`، مع أسهم لوحة المفاتيح وEnter وEscape.
- المظهر فاتح أو داكن أو حسب إعداد الجهاز، ويحفظ في هذا المتصفح. تغييره متاح قبل الدخول ومن الشريط العلوي وإعدادات الحساب؛ تسجيل الخروج وانتهاء الجلسة لا يمسحانه.
- تحميل HTTP يظهر في مؤشر علوي غير حاجب؛ تبقى تنبيهات انتهاء الجلسة وتأكيدات العمليات متاحة.
- قوائم الطلاب والمعلمين والمشرفين تستخدم pagination الخادم مع أحجام صفحات قابلة للتغيير. قائمة الطلاب تدعم أيضًا تصفية الحالة وترتيب سجلات الصفحة الحالية.
- نماذج المالية تعرض صاحب العملية والفترة والعملة؛ الرسم البياني لا يجمع تقارير بعملات أو فترات غير متحققة.
- قائمة الموبايل تحصر التركيز أثناء فتحها، وتعيده لزر الفتح عند الإغلاق، مع استعادة التمرير.

## الرسوم البيانية للإحصائيات

- الرئيسية تعرض أعداد الطلاب والمعلمين النشطين بأعمدة أفقية من `/api/v1/dashboards/statistics`، مع القيم النصية بجوار الرسم. إجمالي المستخدمين يبقى مؤشرًا مستقلًا؛ لا يُجمع مع أدوار المستخدمين في توزيع نسبي.
- الإيرادات والمصروفات الشهرية من `/api/v1/dashboards/revenue-expenses/monthly` تدعم التبديل بين الأعمدة والخطوط، مع جدول للبيانات نفسها. لا يعاد طلب الـ API عند تغيير نوع الرسم، ولا تُجمع أشهر بعملات مختلفة عن عملة التقرير.
- التقارير المالية `/analytics` تعرض مقارنة الفترة السابقة والحالية لكل من الإيرادات والتكاليف وصافي الربح. كل رسم يستخدم قيم وعملة مصدره؛ لا تُحسب أرباح جديدة من مصادر مختلفة أو تُفترض عملة غير واردة.
- تستخدم الرسوم Chart.js وng2-charts الموجودتين في المشروع، وألوان بسطهالي والمظهر الداكن. القيم المفقودة لا تُعرض كأصفار؛ التحميل والخطأ والنتيجة الصفرية لها حالات واضحة وإعادة محاولة عند الفشل.
